#### Flow @start / @listen / @router event orchestration  `[H/M]`
- **Reinforces:** 4c-E project-routing follow-ups (the routeTask/routePick dispatcher + the deferred task→session affinity/tags item)
- **For:** The orchestration NEED behind @start/@listen/@router is real and Shepherd already has half of it. @start (entry firing) and @listen (run when an upstream method completes) are exactly Shepherd's reactive dispatch: shouldFeed (cc-core.lua:1975) edge-triggers the next queued task on a session's fresh transition into `done`, and routeTask/routePick/routePendingDone (cc-core.lua:1981-2084) level-trigger a project's queue to whichever member is free. The honest scope is the small conditional-routing increment, not the engine.

#### Flow join conditions (and_ / or_ barriers)  `[M/M]`
- **Reinforces:** 4c-E routing follow-ups (task→session affinity; the level-triggered project router in cc-core.lua routeTask/routePick/sessionFree)

Building the general nested join tree would be speculative code behind a dead flag, exactly what the 4c-E batch declined.

But the NEED behind and_/or_ — gate a downstream action on the completion state of multiple upstreams — maps cleanly onto Shepherd's one orchestration primitive, the level-triggered router, which already watches done-status across a project's members. OR is effectively present (routePick is a race; first free member wins). The transferable delta is a single AND-barrier predicate: a pure function over a project/group's member statuses that releases a queued feed only when all are done. That is a genuine extension of routing, not a new system — so ADAPT, reinforcing the 4c-E routing follow-ups rather than proposing a parallel FlowCondition engine. Confidence is medium because it directly depends on the same deferred UX call (where the dependency/affinity comes from) that blocks the existing follow-ups, and the nested/arbitrary condition tree should be explicitly dropped — only the flat all-members-done barrier earns its keep.

Ledger a by:"router" barrier-release event like routed feeds already emit. Explicitly do NOT port the nested FlowCondition tree, _execute_racing_listeners, or the event bus — only the flat AND-over-done barrier. Blocked on the same task→affinity UX decision recorded under the 4c-E deferred follow-ups in todos.md.
