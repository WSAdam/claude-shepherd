Template Editor Redesign

The response-template editor already does the right things — {{ autocomplete, drag-in chips, reset paths, save-time validation — and hides almost all of them. This is a rebuild of the form only: same modal, same behaviors, same code paths, restructured so an operator can see what they're about to change and find the variable they need without reading a wall.

01 — The read

What the current screen costs

Five problems, all of them layout and hierarchy. None of them require touching intellisense.ts, model.ts, or any save path.

Wall

27 undifferentiated chips

The palette dumps every variable and the llm() snippet into one flat run of ghost buttons. Nothing groups them, nothing filters them, and the btn-ghost styling gives them no edge — they read as prose, not as draggable objects.

Buried

Blast radius as body copy

“This edits the CATEGORY template — every dispute it wins re-renders it” is the single most consequential fact on the screen, and it's set as a muted grey paragraph the eye skips on the way to the textarea.

Typo

A missing space, shipping

The paragraph renders as …including this.{{variable}} interpolates… — two sentences fused. It's a symptom: that paragraph is carrying scope warning, syntax tutorial, and a cross-reference at once.

Flat

No state, anywhere

Nothing shows whether there are unsaved edits, how close the template is to the 8,000-character ceiling, or which variables are already in use. Save template silently disables itself with no explanation.

Weight

Four buttons, one voice

Reset to template rewrites this dispute's draft. Use default template discards the authored text. Close does nothing. All three carry identical weight, and the two that destroy work sit closest to the primary.

Raw

An unstyled text well

The textarea is a bare monospace box. {{tokens}} — the whole point of the format — get no visual separation from the prose they sit inside, so proofreading a letter means hunting for braces.

Variables

Type {{ in the letter, or drag a chip in
1

The title says what kind of thing this is

A mono eyebrow carries the type — CATEGORY TEMPLATE — and the serif display face carries only the name. The operator learns the scope from the label instead of from a sentence.

was: “Edit template: Default”

2

Blast radius becomes a caution band, not a paragraph

The consequence gets the amber treatment the design system already reserves for “this changes what the thing below it means” — the same tokens the partial-chargeback scope note uses. One sentence, a bolded count, and the exception stated plainly.

The syntax tutorial and the /categories cross-reference move out of here entirely: {{ is explained on the variable rail, where it's used. That also retires the fused-sentence typo.

was: a five-line muted paragraph ending “…including this.{{variable}} interpolates dispute fields (full list on /categories).”

3

The letter gets an editor frame and token highlighting

Variables render as accent-tinted pills, function calls get an outlined treatment, and Markdown headings drop to muted — so scanning for what's interpolated takes a glance instead of a brace-hunt. A single unknown token picks up the amber underline on the spot.

Below it, a hairline meter carries the three numbers that were invisible: character count against the 8,000 ceiling, how many variables are in play, and whether there are unsaved edits.

4

Validation gets a slot instead of a red line

Warnings from templateWarnings() are non-blocking and should look it — amber, with the nearest real variable named. Blocking errors from templateError() use the same slot in --neg, and only those disable the save.

Because the slot is always in the layout, nothing jumps when a message appears.

5

The chip wall becomes a rail with structure

Seven groups derived from the catalog's own labels — Guest, Case, Charge, Refund, Dates, Raw, AI — plus a filter that reaches any of the 27 in a keystroke. The rail scrolls inside a fixed height, so the footer never gets pushed off a short viewport.

Chips become objects: mono type, a grip, a real border. Ones already used in the letter carry the accent and a dot, which turns “what have I not covered?” into a visual question. Hovering shows the catalog label that today only lives in a title attribute.

The {{ autocomplete popup — already built and already good — gets a header, aligned labels, and a keyboard-hint footer so the shortcuts are discoverable rather than folklore.

6

The footer separates intent by weight and by side

The two destructive paths sit left, quiet, and say what they actually do — “Reset this dispute's draft” and “Restore original template” instead of two near-identical “template” labels. Close and Save sit right, in that order, with only Save carrying the accent.

The disabled primary states its reason — No changes to save — rather than greying out silently.

03 — Structure

Three bands and a pinned footer

The modal reads top-to-bottom as three questions in the order an operator asks them. Everything else is chrome.

BandAnswersHolds
Scope “What am I about to change, and who does it hit?” Type eyebrow, template name, close, caution band
Canvas “What does the letter say?” Framed editor, token highlighting, autocomplete, meter, validation slot
Supply “What can I put in it?” Filter, seven groups, chips with used-state, drag affordance
Commit “How do I get out of here?” Destructive left · exits right · one accent
04 — Build

What this costs to ship

Two files carry almost all of it. Every color, radius, shadow, and face already exists in assets/styles.css — the redesign adds component classes, not tokens.
